{#- Overrides Material's `partials/palette.html`. Upstream points each toggle label at `loop.index % loop.length`, i.e. the next entry in the whole palette list. That is right when every palette is a colour mode, but this site also ships a high-contrast palette that has no place on the light/dark toggle. With it in the list, the toggle became a three-state cycle (light -> dark -> high contrast -> light) whose tooltip changed meaning on each press. Declaring no `toggle:` on the high-contrast entry is not enough on its own, because the cycle is computed over `loop.length` -- every entry -- not over the ones that render a label. So the label targets are computed here from the toggle-bearing entries only: light and dark point at each other. Everything else matches upstream, including rendering a radio input for every entry. The palette menu after the form clicks those inputs, which keeps selection and persistence in Material's hands rather than ours. The menu lists every palette: in high contrast the toggle has no label to show, so the menu is also the way back out. -#} {% set toggle_indices = namespace(items=[]) %} {% for option in config.theme.palette %} {% if option.toggle %} {% set toggle_indices.items = toggle_indices.items + [loop.index0] %} {% endif %} {% endfor %}
