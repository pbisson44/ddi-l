    Référence des règles lint¶

    ddi lint et ddi_l.lint.run_lint() vérifient un document selon des règles lint, regroupées en profils. Cette page est générée à partir du registre des règles : elle énumère toutes les règles de la version installée, avec un exemple de ce que chacune signale.

    Descriptions en anglais

    La description de chaque règle provient de sa docstring, rédigée en anglais ; les intitulés autour sont traduits.

    Exécuter le profil par défaut, un profil nommé ou des règles choisies :

    ddi lint etude.xml
ddi lint export.xml --profile colectica-questionnaire --format table
ddi lint export.xml --rules colectica.condition.empty,text.pipe-malformed
ddi lint --list-rules --list-format table

    Un constat est une error, un warning ou une info. Seules les erreurs font échouer ddi lint, sauf si --fail-severity warning ou --fail-severity info demande un contrôle plus strict. Ignorez une règle avec --skip-rule RÈGLE.

    Configurer les règles¶

    Les règles marquées heuristic devinent l'intention d'après la formulation ou la mise en page, et signalent au plus un avertissement. Certaines règles dépendent de conventions qui varient d'un organisme à l'autre ; leurs options sont vides au départ, si bien que la règle ne fait rien tant que vous ne la configurez pas.

    Option Utilisée par Valeur par défaut
    required_languages i18n.missing-language aucune : la règle est inactive
    placeholder_patterns text.placeholder-unresolved ‹‹…››, <<…>>, «insert…», [insert …], « insert survey-specific »
    ui_chrome_tokens text.ui-chrome aucune : la règle est inactive
    logic_note_patterns colectica.statement.logic-note « Flow condition », « Display condition », « Logic: » et leurs équivalents français
    gate_description_patterns colectica.ifthenelse.partial-gate « go to … page », « aller à la page », « passer à la page »
    known_names text.pipe-undeclared aucune
    variable_code_pattern colectica.domain.label-mismatch aucune : la règle est inactive
    pipe_prefixes text.pipe-malformed aucune
    pipe_suffixes text.pipe-undeclared aucune

    En ligne de commande, --required-language (répété) et --known-names FICHIER (un nom par ligne) fixent les deux options dont la plupart des projets ont besoin, et --lint-config FICHIER fixe n'importe quelle option à partir d'un objet JSON :

    {
  "required_languages": ["en-CA", "fr-CA"],
  "ui_chrome_tokens": ["Précédent", "Suivant", "Enregistrer et terminer plus tard"],
  "variable_code_pattern": "Q\\d{3}",
  "pipe_suffixes": ["_E", "_F"]
}

    En Python, lint_configuration() accepte les mêmes options et donne une configuration pour un seul appel, sans changer les autres :

    from ddi_l import read_ddi
from ddi_l.lint import lint_configuration, run_lint

document = read_ddi("mon-etude.xml")
bilingue = lint_configuration(required_languages=["en-CA", "fr-CA"])
constats = run_lint(document, configuration=bilingue)

    run_profile(), document.lint() et les fonctions validate_*() l'acceptent aussi. configure_lint() fixe les mêmes options comme valeur par défaut de tous les appels du processus qui n'en reçoivent pas.

    ddi.agency.allowed¶

    Gravité : error · Profils : par défaut

    Validate that the document agency identifier is present and allowed.

    Exemple de constat :

    Agency 'example.com' is not an allowed value.

    ddi.citation.present¶

    Gravité : error · Profils : par défaut

    Ensure the root document contains a citation element when required.

    Exemple de constat :

    DDIInstance is missing a <Citation> element.

    ddi.citation.title.present¶

    Gravité : error · Profils : par défaut

    Validate that a citation includes a human-readable title when required.

    Exemple de constat :

    Citation is missing a <Title> element.

    ddi.citation.title.languages¶

    Gravité : warning · Profils : par défaut

    Ensure citation titles cover the configured set of languages.

    Exemple de constat :

    Citation title is missing required language 'fr'.

    ddi.maintainable.labels¶

    Gravité : warning · Profils : par défaut

    Ensure maintainable elements include human-readable labels.

    Exemple de constat :

    Maintainable element is missing a label.

    ddi.reference.integrity¶

    Gravité : error (warning in a fragment) · Profils : par défaut, colectica-questionnaire

    Validate that all Reference elements resolve to items present in the document.

    Iterates every element whose tag ends with Reference and whose payload includes a TypeOfObject child (the DDI convention for typed references). Each reference is checked against the identifiable items found by walking the raw XML tree, ensuring coverage of elements not yet natively modelled by the library (e.g. Category inside CategoryScheme).

    A lateBound="true" reference resolves to any version of its item. A reference whose item is present at other versions only is reported by ddi.reference.version, and one recording provenance (inside r:BasedOnObject or r:UserAttributePair) by ddi.reference.provenance-external.

    Exemple de constat :

    Reference to OutParameter '99999999-9999-4999-8999-999999999999' cannot be resolved to an item in this fragment.

    ddi.reference.version¶

    Gravité : warning · Profils : par défaut, colectica-questionnaire

    Report references whose item is present, but not at the version named.

    An exact reference to a version the document does not hold; a late-bound one naming a version newer than any it holds; or a late-bound one whose lateBoundRestriction (latest within major version 4, say) matches no version it holds.

    Exemple de constat :

    Reference to QuestionItem '11111111-1111-4111-8111-000000000001' resolves to its ID, but version 3 is not present; available: 4.

    ddi.reference.provenance-external¶

    Gravité : info · Profils : par défaut, colectica-questionnaire

    Note provenance references whose item is not in the document.

    r:BasedOnReference and references inside r:UserAttributePair record where an item came from; the source usually lives elsewhere.

    Exemple de constat :

    Provenance reference to QuestionItem '11111111-1111-4111-8111-0000000000ff' points outside this file.

    colectica.maintainable.labels¶

    Gravité : warning · Profils : colectica-questionnaire

    Ensure items carry a label or a name, as Colectica content does.

    Colectica items routinely carry a ConstructName, QuestionItemName or r:Name instead of an r:Label. Any of them satisfies the rule, provided it holds text. Used by the colectica-questionnaire profile in place of ddi.maintainable.labels.

    Exemple de constat :

    QuestionConstruct 11111111 has no label or name with text.

    colectica.identifiable.shared-id¶

    Gravité : error · Profils : colectica-questionnaire

    Report an identifiable declared inside two or more different items.

    Colectica's copy of a question can keep the source's OutParameter IDs, so two items declare the same parameter; a binding to it is ambiguous. Versions of one item sharing their children is expected and not reported.

    Exemple de constat :

    OutParameter 33333333 is declared in 2 items: QuestionItem 11111111 (PetKind), QuestionItem 22222222 (PetKind).

    colectica.binding.dangling¶

    Gravité : error · Profils : colectica-questionnaire

    Report a binding whose source or target parameter is not in the file.

    Late-bound references resolve to any version, so only a parameter missing at every version is reported.

    Exemple de constat :

    A binding in Sequence 77777777 (Pet survey) has a source OutParameter 99999999 that is not declared in this file.

    colectica.condition.malformed¶

    Gravité : error · Profils : colectica-questionnaire

    Report a JSON condition that does not parse.

    Neutral and Blaise5DataLookup commands must hold valid JSON.

    Exemple de constat :

    IfThenElse 33333333 (Cat owners): Neutral command is not valid JSON: Expecting value (line 1, column 1).

    colectica.condition.empty¶

    Gravité : error · Profils : colectica-questionnaire

    Report a Neutral condition with no statement at all.

    An empty condition is always true, so the branch always shows. A loop's empty condition tests nothing either, so whether the loop repeats no longer depends on the answers. The intended logic is often in the condition's description, quoted in the message.

    Exemple de constat :

    IfThenElse 33333333 (Cat owners) has an empty condition; its description reads "Show when a cat lives here.".

    colectica.condition.unsatisfiable¶

    Gravité : error · Profils : colectica-questionnaire

    Report a logic group whose And-joined statements contradict each other.

    On one subject: a value and Empty, Empty and Refused, a value and Refused, or two different EqualTo values. Such a group can never be true.

    Exemple de constat :

    IfThenElse 33333333 (No pets) can never be true in group 1 (PetCount): the statements joined by And contradict each other on one subject.

    colectica.condition.native-invalid¶

    Gravité : error · Profils : colectica-questionnaire

    Report native Blaise content that is not a valid condition or program.

    A condition (an IfThenElse's, a loop's, or that of a ComputationItem with no output parameters, such as an edit check) should be one expression over the item's inputs: not statements (goto, set, several lines). A ComputationItem with output parameters holds a program, which may span lines and assign its outputs. Neither should use typographic quotes outside a string or a { comment }, nor name in {{name}} anything but the item's parameters.

    Exemple de constat :

    ComputationItem 66666666 (Many pets) has Blaise code that is not a single valid expression: it uses typographic quotes.

    colectica.condition.unused-inputs¶

    Gravité : warning · Profils : colectica-questionnaire

    Report input parameters of an IfThenElse its conditions never use.

    The inputs are the IfThenElse's, and its ElseIf branches test them too: an input only a branch uses is used, and so is one the item binds onward, to what its branches hold. An item with an empty, unreadable or data-lookup condition in any branch is left alone.

    Exemple de constat :

    IfThenElse 33333333 (Cat owners) has 1 input(s) its condition never uses: PetAge.

    colectica.condition.synopsis-stale¶

    Gravité : info · Profils : colectica-questionnaire

    Report a stored synopsis that does not name a subject the logic tests.

    Colectica stores the synopsis its editor last showed; a synopsis naming another variable, or missing while the condition has statements, no longer describes the logic. The message gives the synopsis rendered from the logic (see ddi_l.colectica_logic.render_synopsis).

    Exemple de constat :

    IfThenElse 33333333 (Cat owners): the stored synopsis does not name PetKind; the logic reads "(PetKind contains all of 3 "Cat") and (PetCount > 2)".

    colectica.ifthenelse.partial-gate¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a gate that wraps only the first construct of a page.

    Heuristic.

    The IfThenElse holds a single construct in its Then branch, more constructs follow it unconditionally in the same sequence, it has no Else branch, and its description says it routes to a page (see gate_description_patterns): the gate probably should wrap the whole page.

    Exemple de constat :

    IfThenElse 33333333 (Owner gate) gates only StatementItem 44444444 (Welcome), while the 2 construct(s) after it in Sequence 55555555 (Owner page) show unconditionally; its description reads "If an owner, go to the owner page". The gate probably should wrap the whole page.

    colectica.codedomain.no-codelist¶

    Gravité : error · Profils : colectica-questionnaire

    Report a CodeDomain without an r:CodeListReference.

    Grid cell domains included.

    Exemple de constat :

    QuestionGrid 11111111 (PetHours) has a code domain with no code list.

    colectica.domain.label-mismatch¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a domain label or item name naming another variable code.

    Heuristic.

    With variable_code_pattern set, the codes it matches in the item's output parameter alias are compared with those in its response domain labels and its names: a label naming only other codes was probably copied from another question.

    Exemple de constat :

    QuestionItem 11111111 (P0012): "P0016" names P0016, but its output is P0012.

    colectica.domain.type-mismatch¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a question whose wording does not fit its domain type.

    Heuristic.

    A question opening with Why (Pourquoi), or What/Which (Quel...) without a date word, whose answer is a date; or one opening with When (Quand) whose answer is a code or text.

    Exemple de constat :

    QuestionItem 11111111 (PetLeft) asks "Why did the pet leave?" but its answer is a date.

    i18n.missing-language¶

    Gravité : error (info for descriptions) · Profils : colectica-questionnaire

    Report text missing a language listed in required_languages.

    Question texts, statement display texts, category labels and numeric or text domain labels are errors; a condition's description is info. Nothing runs until required_languages is configured.

    Exemple de constat :

    Category 22222222 (Bird): the label has no fr-CA.

    text.placeholder-unresolved¶

    Gravité : warning · Profils : colectica-questionnaire

    Report template placeholders left in text (placeholder_patterns).

    Exemple de constat :

    StatementItem 44444444 (Welcome): unresolved placeholder "<<insert pet name>>" in en-CA text.

    text.ui-chrome¶

    Gravité : warning · Profils : colectica-questionnaire

    Report user-interface words pasted into content (ui_chrome_tokens).

    Tokens match whole, case-insensitively. The default list is empty: the words depend on the application the mock-ups came from.

    Exemple de constat :

    StatementItem 44444444 (Goodbye): user-interface text 'Previous', 'Next' in en-CA content.

    text.pipe-malformed¶

    Gravité : error · Profils : colectica-questionnaire

    Report a #{...} pipe that is empty, holds white space, or is a prefix.

    Exemple de constat :

    StatementItem 44444444 (Welcome): the pipe '#{Owner Name}' contains white space.

    text.pipe-undeclared¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a piped #{name} that nothing in the file declares.

    A name is declared by a data lookup field, a parameter alias, or known_names (what the run-time system supplies; --known-names FILE). pipe_suffixes are stripped first.

    Exemple de constat :

    StatementItem 44444444 (Welcome) pipes #{VetName}, which no lookup field, parameter or known name declares.

    colectica.lookup.duplicate-field¶

    Gravité : error · Profils : colectica-questionnaire

    Report a name listed twice in one data lookup's fields.

    Exemple de constat :

    ComputationItem 55555555 (Owner lookup) lists the lookup field 'OwnerName' 2 times.

    colectica.lookup.unlisted-output¶

    Gravité : error · Profils : colectica-questionnaire

    Report a data lookup output its field list does not hold.

    Colectica gives a data lookup one r:OutParameter per field, whose ID is the field's Identifier and whose alias is the field's Name. An output no field lists carries no value, and one named otherwise hands its field on under another name, so whatever binds it reads the wrong thing. A field written without an Identifier is matched by its name.

    Exemple de constat :

    ComputationItem 55555555 (Owner lookup): the output 'OwnerPhone' is not one of its lookup fields.

    colectica.lookup.suspicious-field¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a lookup field never assigned, or named like a value.

    Heuristic.

    A field whose name starts with a digit is more likely a value typed into the wrong place than a field.

    Exemple de constat :

    ComputationItem 55555555 (Owner lookup): the lookup field '01' is named like a value.

    colectica.alias.escape-compounded¶

    Gravité : error · Profils : colectica-questionnaire

    Report an alias whose XML escape was escaped again (_x005F_).

    Escaping a name that already holds an escape turns its underscore into _x005F_, and each further pass doubles it: the alias grows on every propagation and becomes an unusable variable name.

    Exemple de constat :

    OutParameter 88888888 of Sequence 77777777 (Pet survey) has an alias escaped 3 times over (44 characters): 'Pets_x005F_x005F_x002F_Count'.

    colectica.alias.malformed¶

    Gravité : warning · Profils : colectica-questionnaire

    Report an alias with an XML escape, too long, or made of text.

    Heuristic.

    Compounded escapes are reported by colectica.alias.escape-compounded.

    Exemple de constat :

    OutParameter 88888888 of Sequence 77777777 (Pet survey): the alias 'Pets_x002F_Count' holds an XML escape.

    colectica.statement.logic-note¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a statement that is a design note shown as content.

    Heuristic.

    Its name or display text matches logic_note_patterns ("Flow condition: ...", "Display condition", ...). A statement Colectica types as a Note (extension:TypeOfStatement = Note) is not shown, so it is where such a note belongs and is not reported.

    Exemple de constat :

    StatementItem 44444444 (Flow condition) reads "Flow condition: owners only": a design note shown to respondents as content.

    colectica.flow.read-before-computed¶

    Gravité : warning/info · Profils : colectica-questionnaire

    Report an item that reads a value asked or computed later in the flow.

    A condition, a fill or a computation can only read what an earlier question or computation produced: Colectica Designer's routing view reports a later source as broken. The flow is walked in document order, an item reached by several paths (a page reused by several exits, say) once on each, and each input is followed through the bindings of the containers on that path to the question construct or computation that produces it. An input with no binding is left to other rules.

    With the logic extra, the solver also asks whether a respondent can reach the item before the question or computation: if so, the finding gives one; if not, it is info, since only the routing view is affected.

    Exemple de constat :

    IfThenElse 44444444 (Vet gate), reached through IfThenElse 55555555 (Early exit), reads PetAge before QuestionConstruct 66666666 (PetAge) asks it. For example, when PetCount is 2.

    colectica.flow.unreachable¶

    Gravité : warning/info · Profils : colectica-questionnaire

    Report a construct no respondent reaches.

    The gates on every way to it cannot all hold, for any answers: its ask-condition, the disjunction over the ways to it of the gates' conjunction, is unsatisfiable. Only the first construct on a way is reported, not those below it. A condition this rule cannot read (a data lookup, code in another language) may hold or not, and a loop's body counts as reached. Needs the logic extra: without it, a flow with a gate gets one info finding that it was not checked.

    Exemple de constat :

    QuestionConstruct 77777777 (PetFood) is never reached: no answers meet the gates on every way to it.

    colectica.condition.multi-answer-question¶

    Gravité : warning · Profils : colectica-questionnaire

    Report a gate whose condition tests one answer of a multi-answer question.

    Colectica Designer's routing view reports a condition on one answer of a question with several (a StructuredMixedResponseDomain) as broken, even when the answer's output is restated in its domain; a condition on a question with one answer resolves. Ask that answer as a question of its own.

    Exemple de constat :

    IfThenElse 44444444 (Food gate) tests FoodGrams, answer 2 of 2 of QuestionItem 66666666 (PetFood): Designer's routing view reports a condition on one answer of a question with several as broken. Ask it as a question of its own.
