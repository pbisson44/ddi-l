    Module 1: What is metadata and why does it matter?¶

    Exercises¶

    Exercise 1

    Any three of these, or similar:

    1. What does each column mean? (Is A an age? In years or months?)
    2. What unit is column C in? (Dollars? Euros? Per year or per month?)
    3. Who was surveyed? (Students? Adults? Everyone?)
    4. When was the data collected?

    Exercise 2

    1. Metadata is information that describes data: what it means, where it came from, and how it was collected.
    2. Metadata: any two of the title "Campus Sleep Study 2025", the collection date (September 2025), the population (first-year students), the column name sleep_hrs, or its meaning (hours of sleep on a typical school night). Data: any of the values 7, 6, or 8.

    Exercise 3

    1-c, 2-d, 3-b, 4-a.

    • Findable (c): the catalog can only find what is described in structured fields.
    • Accessible (d): a standard, open format needs no special software.
    • Interoperable (b): a shared code list means the same code has the same meaning in both surveys, so the data can be combined.
    • Re-usable (a): a new user knows exactly what the data contains.

    Exercise 4

    For example: "DDI, the Data Documentation Initiative, is an international standard for describing surveys, censuses, and datasets in XML. National statistics offices, data archives, universities, and research teams use it so that others can find, understand, and reuse their data."

    Any two of these kinds of organizations are correct: national statistics offices, data archives or national libraries, universities and their research repositories, research teams.

    Exercise 5

    Does: 1, 3, and 5. Does not: 2 and 4.

    For example: "ddi-l creates, reads, updates, and validates DDI metadata from Python, but it does not collect survey answers."

    Quiz¶

    Question 1 (O1): A spreadsheet has a column headed Age (years) with the values 34, 28, and 45. Which of these is metadata?

    B. Metadata is information about data. The header tells you what the numbers mean and how they are measured. The values themselves, and anything computed from them, are data.

    Question 2 (O2): A colleague sends a table with columns A, B, and C and no notes. Column C holds values like 52000. You want to report the average income. Which question must you answer first?

    D. Without knowing that C is income, and whether it is in dollars or euros, per year or per month, any average you report could be wrong. The other questions do not change what the numbers mean.

    Question 3 (O3): Which sentence best describes DDI?

    A. DDI is a standard: a set of agreed rules for documentation. Option C confuses DDI with tools; ddi-l is a Python package that works with DDI, and it does not compute statistics.

    Question 4 (O4): Your survey and a survey in France use the same DDI code list for gender, so the two datasets can be merged. Which FAIR principle does this support most directly?

    C. Interoperable means data works with other data. A shared code list gives each code the same meaning in both datasets, so they can be combined and compared.

    Question 5 (O4): A data catalog reads the title, agency, and concepts in your DDI file, so a search for 'mental health survey' lists your dataset. Which FAIR principle does this support?

    A. Findable means people can discover the data. Structured DDI fields give catalogs something reliable to index and search.

    Question 6 (O5): Which of these tasks does ddi-l NOT do?

    B. ddi-l works with metadata: it creates, reads, updates, and validates DDI documents. Collecting answers is the job of a survey tool.

    Module 2: Set up your Python environment¶

    Exercises¶

    Exercise 1

    For example, Python 3.12.3: yes, because 3.12 is 3.11 or newer. If you see Python 3.10.12 or older, the answer is no: install a newer Python from https://www.python.org/downloads/ before you continue.

    Exercise 2

    The last line starts with Successfully installed and lists ddi-l-... among the packages (the version may vary). If the packages were already installed, pip says Requirement already satisfied instead. Both mean you are ready. A line starting with ERROR means the install failed.

    Exercise 3

    The installed version, such as 0.1.0 or later. If you see ModuleNotFoundError instead, ddi-l is not installed in this Python: go back to Exercise 2.

    Exercise 4

    1. validate ("Validate an XML document against the DDI schema.")
    2. lint ("Lint a DDI document and report findings as JSON.")
    3. versions ("List supported DDI schema releases.")

    Exercise 5

    1. Python REPL: it is the quickest way to run one line you do not need to keep.
    2. Script file: it saves your code, and python my_script.py runs it again from the top.
    3. Notebook: it shows notes, code, and output together, step by step.

    Other choices are fine if your reason holds up; for example, a notebook also saves your code for task 2.

    Quiz¶

    Question 1 (O1): python --version prints Python 3.10.12. What should you do before you install ddi-l?

    B. ddi-l requires Python 3.11 or newer, and 3.10 is older. Install a newer Python, then install ddi-l with it.

    Question 2 (O2): The last line of pip install ddi-l pandas openpyxl reads Requirement already satisfied. What does this mean?

    D. Requirement already satisfied means the package is already there. A failed install ends with a line that starts with ERROR.

    Question 3 (O3): You run import ddi_l as ddi and get ModuleNotFoundError: No module named 'ddi_l'. What is the most likely cause?

    A. Python cannot find the package, so it is not installed for this Python. Run pip install ddi-l again, or python3 -m pip install ddi-l if you start Python with python3. Option B is not valid Python: a hyphen cannot appear in an import name, which is why the module is called ddi_l.

    Question 4 (O4): You want to check a file against the DDI schema from the terminal. Which command from the ddi --help list do you use?

    C. Its description reads "Validate an XML document against the DDI schema." roundtrip re-writes a file, to-json converts it, and serve runs the HTTP API.

    Question 5 (O5): You will build a study over several days and want to run the whole thing again from the top with one command after each change. Which workspace fits best?

    B. A script file keeps your code, and one command runs all of it again. The REPL forgets what you typed when you close it.

    Module 3: Create your first DDI study¶

    Exercises¶

    Exercise 1

    import ddi_l as ddi

doc = ddi.new_study(title="Student Well-Being Survey", agency="university.edu")

q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="How would you rate your health?")
q3 = doc.add_question(text="How many hours do you sleep per night?")

print(f"Questions: {len(doc.questions)}")  # -> Questions: 3
for q in doc.questions:
    print(q.identifier)

doc.save("well-being.xml")

    Exercise 2

    The question text sits in a <d:Text> element, inside <d:LiteralText> inside <d:QuestionText>:

    <d:Text xml:lang="en" isPlainText="true">What is your age?</d:Text>

    Exercise 3

    from ddi_l.models.base import InternationalString

print(f"Schema problems: {len(doc.validate())}")  # -> Schema problems: 0
print(f"Lint findings: {len(doc.lint())}")  # -> Lint findings: 3

q1.labels.append(InternationalString(text="Age", lang="en"))
q2.labels.append(InternationalString(text="Self-rated health", lang="en"))
q3.labels.append(InternationalString(text="Hours of sleep", lang="en"))

print(f"Lint findings: {len(doc.lint())}")  # -> Lint findings: 0
doc.save("well-being.xml")

    The three warnings were "Maintainable element is missing a label.", one per question. A label fixes each one.

    Exercise 4

    q1.question_texts.append(InternationalString(text="Quel est votre âge ?", lang="fr"))
q1.labels.append(InternationalString(text="Âge", lang="fr"))

print(f"Questions: {len(doc.questions)}")  # -> Questions: 3
print(f"Lint findings: {len(doc.lint())}")  # -> Lint findings: 0
doc.save("well-being.xml")

    The count stays at 3 because both translations belong to q1. In the XML, the first question now reads:

  <r:Content xml:lang="fr">Âge</r:Content>
</r:Label>
<d:QuestionText>
  <d:LiteralText>
    <d:Text xml:lang="en" isPlainText="true">What is your age?</d:Text>

  </d:LiteralText>
</d:QuestionText>

    Quiz¶

    Question 1 (O1): You run doc = ddi.new_study(title='Sleep Survey') and get a TypeError. Why?

    B. ddi.new_study() requires both title= and agency=. The error message says so: "missing 1 required keyword-only argument: 'agency'".

    Question 2 (O1): After q1 = doc.add_question(text='What is your age?'), what is q1?

    C. doc.add_question() adds a question item to the study and returns that question object. Keeping it in a variable lets you work with it later.

    Question 3 (O2): A study has three questions. You add a fourth with doc.add_question(), then run print(len(doc.questions)). What is printed?

    A. doc.questions is the list of every question in the study, and len() counts them: three plus the new one.

    Question 4 (O3): You open the file written by doc.save('well-being.xml'). Where do you find the text of your first question?

    A. doc.save() writes the whole study, and each question's text sits in <d:Text>, inside <d:LiteralText>, inside <d:QuestionText>.

    Question 5 (O4): You want the first question, q1, in both English and French. Which line does it?

    C. Appending an InternationalString with the new language stores both versions in the same question item. Option A creates a brand-new, separate question, not a translation of q1.

    Question 6 (O5): doc.validate() returns an empty list, but doc.lint() reports warnings. Is the document valid DDI?

    D. An empty list from doc.validate() means the document follows the DDI schema. Lint warnings are worth fixing, but they do not make the document invalid.

    Question 7 (O5): doc.lint() reports 'Maintainable element is missing a label.' once for each of your three questions. Which change clears the warnings?

    B. The warning names the problem: the questions have no label. Saving or validating does not change the document, and adding the questions again with the same code brings the same warnings back.

    Module 4: Add variables and link them to questions¶

    Exercises¶

    Exercise 1

    For example: "A variable is one column of a data file, such as SleepHours, which holds every student's answer to the same question: how many hours they sleep per night."

    Exercise 2

    import ddi_l as ddi

doc = ddi.new_study(title="Student Well-Being Survey", agency="university.edu")

q1 = doc.add_question(text="What is your age?", label="Age")
q2 = doc.add_question(text="How would you rate your health?", label="Self-rated health")
q3 = doc.add_question(
    text="How many hours do you sleep per night?", label="Hours of sleep"
)

v1 = doc.add_variable(name="Age", label="Age in years", question=q1)
v2 = doc.add_variable(
    name="HealthRating", label="Self-rated health, 1 to 5", question=q2
)
v3 = doc.add_variable(name="SleepHours", label="Hours of sleep per night", question=q3)

print(f"Schema problems: {len(doc.validate())}")  # -> Schema problems: 0
print(f"Lint findings: {len(doc.lint())}")  # -> Lint findings: 0

    If doc.lint() reports "Maintainable element is missing a label.", one of your questions or variables has no label=.

    Exercise 3

    print(f"Variables: {len(doc.variables)}")  # -> Variables: 3
for v in doc.variables:
    print(v.identifier)

    Each identifier is a UUID, such as a1b2c3d4-....

    Exercise 4

    For example: "The link leads to the question 'How would you rate your health?', so my colleague knows the values are each student's own rating of their health. Without it, they might guess wrongly, for example that the values were measured by a doctor, or that 1 means the best health."

    Exercise 5

    doc.save("well-being.xml")
print(q1.identifier)

    The variable's name is in <l:VariableName>:

    <l:VariableName>
  <r:String xml:lang="en">Age</r:String>
</l:VariableName>

    The <r:ID> inside the <r:QuestionReference> a few lines below is the same identifier that print(q1.identifier) shows. That shared identifier is the link from the variable to the question.

    Quiz¶

    Question 1 (O1): In a table with the columns Age, HealthRating, and SleepHours, which of these is a variable?

    C. A variable is like a column. Each column holds one type of information, such as a health rating, for every person in the dataset. A row is one person; a value is one answer.

    Question 2 (O2): What happens when you run doc.add_variable(name='Age', question='What is your age?')?

    B. question= needs the object that doc.add_question() returned. A plain string is not a question, so the call fails with an AttributeError. Pass q1 instead.

    Question 3 (O2): What does question=q2 do in doc.add_variable(name='HealthRating', question=q2)?

    A. The question= argument stores a link between the variable and the question that collected the data. You can see it in the XML as <r:QuestionReference>.

    Question 4 (O3): Which code prints the identifier of every variable in the study?

    D. doc.variables is a list, so you loop through it and print each variable's identifier. Option A fails because a list has no identifier, and option C loops through the questions, not the variables.

    Question 5 (O4): A data user sees the column SleepHours and wants to know exactly what was asked. How does the link from the variable to its question help?

    B. This is traceability: the link takes the user from the data column back to the exact question that collected the data.

    Question 6 (O5): In the saved XML, which element links a variable to the question that collected it?

    C. <r:QuestionReference> sits inside the <l:Variable> element and holds the question's identifier. <l:VariableName> holds the variable's name, and <d:QuestionText> belongs to the question itself.

    Module 5: Organize with concepts and universes¶

    Exercises¶

    Exercise 1

    • Nutrition: concept.
    • Adults aged 18+ in Canada: universe.
    • Sleep quality: concept.
    • Public schools in Ontario: universe.
    • Employment: concept.
    • Children aged 6 to 11 living in private households: universe.

    A concept is the idea that a variable measures, such as "Nutrition". A universe is the group of people or things a study covers, such as "Adults aged 18+ in Canada".

    Exercise 2

    import ddi_l as ddi

doc = ddi.new_study(title="National Health Survey", agency="health.gc.ca")

demo = doc.add_concept(name="Demographics")
activity = doc.add_concept(name="Physical Activity")
nutrition = doc.add_concept(name="Nutrition")

doc.add_universe(name="Adults aged 18+ in Canada")

print(f"Concepts: {len(doc.concepts)}")  # -> Concepts: 3
print(f"Universes: {len(doc.universes)}")  # -> Universes: 1

    Exercise 3

    q1 = doc.add_question(text="How old are you?")
q2 = doc.add_question(text="What is your weight in kg?")
q3 = doc.add_question(text="How many days per week do you exercise?")
q4 = doc.add_question(text="How many servings of fruit do you eat per day?")

doc.add_variable(name="Age", question=q1, concept=demo)
weight = doc.add_variable(name="Weight", question=q2, concept=demo)
doc.add_variable(name="ExerciseFrequency", question=q3, concept=activity)
doc.add_variable(name="FruitServings", question=q4, concept=nutrition)

linked = weight.concept_references[0].identifier == demo.identifier

print(f"Questions: {len(doc.questions)}")  # -> Questions: 4
print(f"Variables: {len(doc.variables)}")  # -> Variables: 4
print(f"Weight is linked to Demographics: {linked}")
print(f"Schema problems: {len(doc.validate())}")  # -> Schema problems: 0

    Exercise 4

    print("Concepts:")
for concept in doc.concepts:
    print(f"  {concept.names[0].text}")

print("Universes:")
for universe in doc.universes:
    print(f"  {universe.names[0].text}")

    Quiz¶

    Question 1 (O1): Which phrase is the universe of this study?

    A. The universe says who is studied. "Sleep quality" and "Stress" say what is measured, so they are concepts. A question is neither.

    Question 2 (O1): Which sentence correctly explains a concept?

    C. A concept is an abstract idea that variables measure. Option A describes a universe, and option B describes a code list.

    Question 3 (O2): What does this code print?

    D. Two calls to doc.add_concept() add two concepts, and one call to doc.add_universe() adds one universe.

    Question 4 (O3): The variable Age is not linked to its concept. Which call fixes it?

    B. Pass the concept with concept= when you call doc.add_variable(). The other calls do not exist.

    Question 5 (O4): Which loop prints the name of every universe?

    C. Each universe keeps its name in names; names[0].text is the text. Option A prints the whole object, option B fails because a list has no names, and option D loops over the concepts.

    Module 6: Open, modify, and re-save existing DDI files¶

    Exercises¶

    Exercise 1

    import ddi_l as ddi

# Create and save
doc = ddi.new_study(title="Census 2024", agency="stats.example.org")
q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="What is your gender?")
v1 = doc.add_variable(name="Age", question=q1)
v2 = doc.add_variable(name="Gender", question=q2)
doc.save("census-2024.xml")
print("Saved.")

# Re-open and inspect
doc2 = ddi.open_ddi("census-2024.xml")
print(f"Questions: {len(doc2.questions)}")  # -> Questions: 2
print(f"Variables: {len(doc2.variables)}")  # -> Variables: 2

    Exercise 2

    try:
    ddi.open_ddi("census-2024-broken.xml", validate=True)
except ddi.DDIValidationError as error:
    print(f"Not valid: {error}")

unchecked = ddi.open_ddi("census-2024-broken.xml")
print(f"Opened without checking: {len(unchecked.questions)} questions")

    The path after at points to the Version element directly under DDIInstance. Its value, one, does not match the pattern for versions: [0-9]+(\.[0-9]+)* means digits, optionally followed by more groups of a dot and digits, such as 1 or 1.0.0.

    Without validate=True, the broken file opens with no complaint. Only validation tells you that the file breaks the DDI rules.

    Exercise 3

    q3 = doc2.add_question(text="What is your marital status?")
q4 = doc2.add_question(text="How many people live in your household?")
v3 = doc2.add_variable(name="MaritalStatus", question=q3)
v4 = doc2.add_variable(name="HouseholdSize", question=q4)

doc2.questions[0].question_texts[0].text = "What was your age at your last birthday?"

statuses = doc2.add_code_list(name="Marital Status Codes")
v3.set_coded(statuses)

errors = doc2.validate()
if errors:
    print("Validation errors:", errors)
else:
    print("Document is valid.")
    doc2.save("census-2024-updated.xml")
    print("Saved updated file.")

    Exercise 4

    doc3 = ddi.open_ddi("census-2024-updated.xml")
print(f"Questions: {len(doc3.questions)}")  # -> Questions: 4
print(f"Variables: {len(doc3.variables)}")
print(f"Code lists: {len(doc3.code_lists)}")
print(f"First question: {doc3.questions[0].question_texts[0].text}")

original = ddi.open_ddi("census-2024.xml")
print(f"Original questions: {len(original.questions)}")

    The counts grew in the new file, and the original kept its two questions: saving under a new filename left it untouched.

    Exercise 5

    partner = ddi.open_ddi("census-2024-partner.xml", validate=True)
partner.add_variable(name="Region")
partner.save("census-2024-partner-updated.xml")

saved = Path("census-2024-partner-updated.xml").read_text(encoding="utf-8")
print("Persons living in private households" in saved)  # -> True

    The element survives: ddi-l keeps XML it does not model exactly as it was, so opening and saving a file never deletes content you did not touch. This is the round-trip guarantee.

    Quiz¶

    Question 1 (O1): What does this code print for a file with 3 questions and 5 variables?

    D. ddi.open_ddi() reads the whole file. doc.questions and doc.variables list its questions and variables, in that order in the print() call.

    Question 2 (O2): What is wrong with this file?

    B. The path after at names the element: Version, under DDIInstance. The first part of the message says its value does not match the pattern for version numbers.

    Question 3 (O3): Which line codes the variable v with the code list levels?

    C. set_coded() is a method of the variable, and it takes the code list as its argument. doc.add_code_list() creates a new list; it does not code a variable.

    Question 4 (O4): What does my-study.xml contain afterwards?

    A. Changes live only in memory until you call doc.save(). The file on disk is unchanged.

    Question 5 (O5): What happens to an element that ddi-l does not model?

    D. This is the round-trip guarantee: content that ddi-l does not recognize passes through the read-and-write cycle untouched.

    Module 7: Validate from the command line¶

    Exercises¶

    Exercise 1

    ddi validate census-2024.xml

    The output says Document is valid., so the file follows all the DDI schema rules.

    Exercise 2

    cp census-2024.xml broken.xml
# edit line 5 of broken.xml, then:
ddi validate broken.xml
    • What: the value one does not match the pattern for versions. [0-9]+(\.[0-9]+)* means digits, optionally followed by more groups of a dot and digits, such as 1 or 1.0.0.
    • Where: the path after at ends with DDIInstance, then Version: the Version element directly under the root, which is the one on line 5. The context: line confirms the value found: one.

    Exercise 3

    ddi lint census-2024.xml --format table

    One finding: severity warning, rule ddi.maintainable.labels, message "Maintainable element is missing a label." The file has four of them: its two questions and two variables have no label. To fix them, pass label= when you add each item, as in Section 9 of Module 3. The file is still valid: warnings point to quality, not to schema errors.

    Exercise 4

    from uuid import uuid4

import ddi_l as ddi
from ddi_l.models.base import InternationalString, VersionRationale
from ddi_l.models.logicalproduct import Category, CodeItem

ARCHIVE_FIELDS = {
    "archive:accession_date": "Date the archive received the file.",
    "archive:depositor": "Team that deposited the file.",
    "archive:retention": "How long the archive keeps the file.",
    "archive:access": "Who may use the data: open, registered or restricted.",
}
YES_NO_FILES = {3}  # from the plan: study 3 asks a yes/no question


def set_archive_field(item, key, value):
    if key not in ARCHIVE_FIELDS:
        raise KeyError(f"{key!r} is not in the archive catalog")
    item.set_property(key, value)


def count_archive_fields(doc):
    items = [doc.study_unit, *doc.questions, *doc.variables]
    return sum(
        any(key.startswith("archive:") for key in item.properties) for item in items
    )


for i in (1, 2, 3):
    doc = ddi.open_ddi(f"study-{i}.xml")
    if not doc.concepts:
        doc.add_concept(name="Social Sciences")
    if not doc.universes:
        doc.add_universe(name="General population")
    variable, question = doc.variables[0], doc.questions[0]
    if not variable.question_references:
        variable.question_references = [question.to_reference()]
    if i in YES_NO_FILES:
        yes_no = doc.add_code_list(name="Yes/No")
        for value, label in (("1", "Yes"), ("2", "No")):
            category = doc.add_item(Category, name=label, label=label)
            yes_no.codes.append(
                CodeItem(
                    agency=yes_no.agency,
                    identifier=str(uuid4()),
                    version=yes_no.version,
                    value=value,
                    category=category.to_reference(),
                )
            )
        variable.set_coded(yes_no)

    study = doc.study_unit
    set_archive_field(study, "archive:accession_date", "2024-11-04")
    set_archive_field(study, "archive:depositor", f"Research team {i}")
    set_archive_field(study, "archive:retention", "permanent")
    set_archive_field(variable, "archive:access", "open")

    study.increment_minor_version(allow_dotted=True)
    study.version_rationales.append(
        VersionRationale(
            descriptions=[
                InternationalString(
                    text="Enriched metadata: added concept, universe, question link and archive fields"
                )
            ]
        )
    )
    study.version_responsibility = "Archive Metadata Team"

    lint_errors = [f for f in doc.lint() if f.severity == "error"]
    print(
        f"study-{i}: {len(doc.validate())} validation errors, "
        f"{len(lint_errors)} lint errors, "
        f"{count_archive_fields(doc)} items with archive fields"
    )
    doc.save(f"study-{i}-enriched.xml")
