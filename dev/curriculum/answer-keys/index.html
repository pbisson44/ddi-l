    Module 1: What is metadata and why does it matter?¶

    Exercises¶

    Exercise 1

    Any three of these, or similar:

    1. What each column means (is A an age? In years or months?)
    2. Who was surveyed (students? adults? everyone?)
    3. When the data was collected

    Exercise 2

    For example: "The Data Documentation Initiative (DDI) is an international standard for describing data from the social, behavioral, economic, and health sciences."

    Quiz¶

    Question 1: What is metadata?

    B. Metadata is information about data. It describes what the data means, where it came from, and how it was collected.

    Question 2: Why does documentation matter?

    C. Without documentation, data is just numbers and labels with no context. People may misinterpret or misuse the data.

    Question 3: What does FAIR stand for?

    B. FAIR stands for Findable, Accessible, Interoperable, and Re-usable. These four principles guide how data should be shared so that others can discover, understand, and reuse it. DDI metadata helps you meet all four.

    Question 4: What does ddi-l do?

    B. ddi-l is a Python package for working with DDI metadata documents. It handles the XML so you can focus on your data.

    Module 2: Set up your Python environment¶

    Exercises¶

    Exercise 1

    The last line starts with Successfully installed and lists ddi-l-... among the packages (the version may vary). If the packages were already installed, pip says Requirement already satisfied instead.

    Exercise 2

    The installed version, such as 0.1.0 or later.

    Exercise 3

    Eight in ddi-l 0.1.0: validate, to-json, from-json, roundtrip, lint, versions, to-jsonld and serve. Later versions may add more.

    Quiz¶

    Question 1: What is the minimum Python version for ddi-l?

    C. ddi-l requires Python 3.11 or newer.

    Question 2: Which command shows the ddi-l CLI help?

    C. The command ddi --help shows the list of commands available in the ddi-l command-line tool.

    Question 3: What does pip install do?

    B. pip install downloads a package from PyPI (the Python Package Index) and installs it on your computer so you can use it.

    Module 3: Create your first DDI study¶

    Exercises¶

    Exercise 1

    import ddi_l as ddi

doc = ddi.new_study(title="Student Well-Being Survey", agency="university.edu")

q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="How would you rate your health?")
q3 = doc.add_question(text="How many hours do you sleep per night?")

print(f"Questions: {len(doc.questions)}")
doc.save("well-being.xml")

    Exercise 2

    The question text sits in a <d:Text> element, inside <d:LiteralText> inside <d:QuestionText>:

    <d:Text xml:lang="en" isPlainText="true">What is your age?</d:Text>

    Exercise 3

    from ddi_l.models.base import InternationalString

q1.question_texts.append(InternationalString(text="Quel est votre âge ?", lang="fr"))
doc.save("well-being.xml")

    Open the XML. You should see both xml:lang="en" and xml:lang="fr" entries for the first question.

    Quiz¶

    Question 1: What does ddi.new_study() return?

    B. ddi.new_study() returns a Document object. You use this object to add questions, variables, and other items to the study.

    Question 2: What does doc.add_question() do?

    B. doc.add_question() adds a new question item to the DDI study. It returns the question object so you can use it later.

    Question 3: What does doc.save() do?

    C. doc.save("filename.xml") writes the DDI document to an XML file in your current folder.

    Question 4: How do you add a French translation to a question?

    B. To add a translation, append an InternationalString with the new language to the question's question_texts list. Both language versions are stored in the same question item. Option A would create a brand-new question, not a translation of an existing one.

    Question 5: How do you count the questions in a study?

    B. doc.questions gives you the list of questions, and len() counts how many items are in that list.

    Question 6: doc.validate() returns an empty list, but doc.lint() reports warnings. Is the document valid DDI?

    B. An empty list from doc.validate() means the document follows the DDI schema. Lint warnings are worth fixing, but they do not make the document invalid.

    Module 4: Add variables and link them to questions¶

    Exercises¶

    Exercise 1

    import ddi_l as ddi

doc = ddi.new_study(title="Student Well-Being Survey", agency="university.edu")

q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="How would you rate your health?")
q3 = doc.add_question(text="How many hours do you sleep per night?")

v1 = doc.add_variable(name="Age", question=q1)
v2 = doc.add_variable(name="HealthRating", question=q2)
v3 = doc.add_variable(name="SleepHours", question=q3)

print(f"Variables: {len(doc.variables)}")

    Exercise 2

    for v in doc.variables:
    print(v.identifier)

    Each identifier is a UUID, such as a1b2c3d4-....

    Exercise 3

    Each variable is an <l:Variable> element. Its name is in <l:VariableName>, for example:

    <l:VariableName>
  <r:String xml:lang="en">Age</r:String>
</l:VariableName>

    The <r:QuestionReference> just below it is the link to the question.

    Quiz¶

    Question 1: What does the question= argument do in doc.add_variable()?

    B. The question= argument creates a link in the DDI document between the variable and the question that collected the data.

    Question 2: How do you list all variables in a study?

    C. doc.variables returns the list of all variables in the study. You can use len(doc.variables) to count them.

    Question 3: A variable is like a _____ in a spreadsheet.

    C. A variable is like a column. Each column holds one type of information (such as age or income) for every person in the dataset.

    Module 5: Organize with concepts and universes¶

    Exercises¶

    Exercise 1

    import ddi_l as ddi

doc = ddi.new_study(title="National Health Survey", agency="health.gc.ca")

q1 = doc.add_question(text="How old are you?")
q2 = doc.add_question(text="What is your weight in kg?")
q3 = doc.add_question(text="How many days per week do you exercise?")
q4 = doc.add_question(text="How many servings of fruit do you eat per day?")

demo = doc.add_concept(name="Demographics")
activity = doc.add_concept(name="Physical Activity")
nutrition = doc.add_concept(name="Nutrition")

doc.add_universe(name="Adults aged 18+ in Canada")

doc.add_variable(name="Age", question=q1, concept=demo)
doc.add_variable(name="Weight", question=q2, concept=demo)
doc.add_variable(name="ExerciseFrequency", question=q3, concept=activity)
doc.add_variable(name="FruitServings", question=q4, concept=nutrition)

print(f"Questions: {len(doc.questions)}")
print(f"Variables: {len(doc.variables)}")
print(f"Concepts: {len(doc.concepts)}")
print(f"Universes: {len(doc.universes)}")
print(f"Schema problems: {len(doc.validate())}")

    Quiz¶

    Q1: What is a concept?

    B. A concept is an abstract idea, like "Demographics" or "Nutrition." Variables measure concepts.

    Q2: What is a universe?

    C. The universe tells you who the survey covers, for example, "Adults aged 18+ in Canada."

    Q3: How do you link a variable to a concept?

    B. Pass the concept= argument when you call doc.add_variable().

    Module 6: From a CSV or Excel Table to DDI¶

    Quiz¶

    Q1: What does csv.DictReader give you?

    B. csv.DictReader reads a CSV file. Its fieldnames property returns the column names from the first row.

    Q2: How do you get column names from a pandas DataFrame?

    C. Use df.columns to get the column names from a pandas DataFrame. Wrap it in list() to get a plain list.

    Q3: What does the script produce?

    B. The script produces a DDI XML file. This file describes the data (variable names, questions, concepts) but does not contain the data itself.

    Q4: Why should you add concepts after importing columns?

    C. Concepts group related variables together. Without them, you just have a flat list of names. Concepts add meaning and structure.

    Quiz¶

    Question 1: What does ddi.open_ddi() do?

    B. ddi.open_ddi() reads a DDI XML file and returns a Document object that you can inspect and modify.

    Question 2: What does validate=True do when you call open_ddi()?

    B. When you pass validate=True, open_ddi() runs the DDI schema check during loading. If the file has errors, you get an error message right away.

    Question 3: Is existing content lost when you open a file, add items, and save it?

    C. ddi-l preserves unknown XML elements. This is called the round-trip guarantee. Content that ddi-l does not recognize passes through unchanged.

    Module 7: Validate from the command line¶

    Exercises¶

    Exercise 1

    ddi validate census-2024-updated.xml

    Exercise 2

    ddi to-json census-2024-updated.xml --indent 2 > census-2024-updated.json
wc -l census-2024-updated.json

    The wc -l command counts the number of lines in a file. Your number will depend on how much content the file has.

    Exercise 3

    ddi roundtrip census-2024-updated.xml --output census-2024-roundtrip.xml
ls -l census-2024-updated.xml census-2024-roundtrip.xml

    The ls -l command shows the file sizes. The two files should be close in size. Small differences in whitespace are normal.

    Quiz¶

    Question 1: What does the ddi validate command do?

    B. ddi validate checks the file against the DDI schema. If the file follows all the rules, it prints "Document is valid." If not, it prints a list of errors in JSON format.

    Question 2: What does exit code 0 mean?

    C. Exit code 0 means success. The command finished without errors. Scripts and pipelines use exit codes to decide what to do next.

    Question 3: What does ddi to-json produce?

    B. ddi to-json converts a DDI XML file into JSON format. JSON is a text format that many tools and programming languages can read.

    Module 7: Build Code Lists and Controlled Vocabularies¶

    Quiz¶

    Q1: What is a code list?

    B. A code list defines the allowed answers for a question. For example, "Male / Female / Other" for gender.

    Q2: How do you add a category to a document?

    B. Use doc.add_item(Category, name="Male"). You must import Category from ddi_l.models.logicalproduct first.

    Q3: How do you get all categories in a document?

    C. Use doc.items(Category) to get a list of all Category items. This works for any registered DDI type.

    Q4: Why do code lists matter?

    C. Code lists prevent messy, inconsistent answers. They also let different surveys share the same set of allowed values, making data comparable.

    Module 8: From a CSV or Excel table to DDI¶

    Exercises¶

    Exercise 1

    import csv
import ddi_l as ddi

with open("survey_sample.csv") as f:
    reader = csv.DictReader(f)
    columns = reader.fieldnames

# The question each column records, worded the way respondents saw it
QUESTIONS = {
    "age": "How old are you?",
    "gender": "What is your gender?",
    "income": "What was your total income last year, before taxes?",
    "education_level": "What is the highest level of education you have completed?",
}

doc = ddi.new_study(title="Household Survey", agency="research.org")
for col in columns:
    wording = QUESTIONS.get(col)
    # A column nobody was asked about, such as respondent_id, gets no question
    q = doc.add_question(text=wording) if wording else None
    doc.add_variable(name=col, question=q)

doc.save("household-survey.xml")
print(f"Variables: {len(doc.variables)}")  # -> Variables: 5

    Module 8: Map a Questionnaire to DDI Flow Logic¶

    Quiz¶

    Q1: What DDI construct represents an ordered section of a questionnaire?

    B. A Sequence groups steps in order, like a section of a questionnaire.

    Q2: How do you model 'skip to Section C if age < 16' in DDI?

    C. An IfThenElse checks the age condition and routes the respondent to Section B (then) or Section C (else).

    Q3: What is the purpose of a QuestionConstruct?

    B. A QuestionConstruct wraps a question reference so the question can participate in the flow logic (be placed in a Sequence, be the target of an IfThenElse, etc.).

    Q4: What DDI construct repeats a section for each household member?

    D. A Loop repeats a control construct (usually a Sequence) for each item in a list, such as each household member.

    Q5: What is the first step when mapping a questionnaire spec to DDI?

    C. Start by identifying all the questions in the spec and creating a QuestionConstruct for each one. Then build the Sequences and flow logic around them.

    Module 9: Document Data Files and Variable Lineage¶

    Quiz¶

    Q1: What does source_variable_references track?

    B. source_variable_references is a list of Reference objects pointing to the variables that were used to compute a derived variable.

    Q2: How do you link a variable to its source question?

    C. The question= parameter in doc.add_variable() creates the link automatically via question_references.

    Q3: In the three-file model, what does the production file contain?

    C. The production file has both the original collection variables (with based-on references) and new derived variables (with source variable references).

    Q4: A BMI variable is computed from height and weight. How many source_variable_references does it have?

    C. BMI has 2 source variable references, one for height and one for weight, because it is derived from both.

    Q5: What is the purpose of data lineage?

    B. Data lineage lets you follow any variable, even in the final master file, all the way back to the original collection variable and the question that generated it.

    Module 10: Data Linkage: Combining Records Across Datasets¶

    Quiz¶

    Q1: What is data linkage?

    B. Data (microdata) linkage combines records from different files that describe the same person, household, or business, using the variables they have in common.

    Q2: What is the linkage key?

    B. The linkage key is the common variable (here, anon_id) used to join records that belong to the same unit. We tag it with set_property("linkage_role", "key").

    Q3: How does deterministic linkage differ from probabilistic linkage?

    A. Deterministic linkage matches on a reliable exact key. Probabilistic linkage combines weighted agreement across several fields (name, date of birth, sex, postal code) and applies a threshold.

    Q4: How do you record that a linked variable draws on two source files?

    B. source_variable_references holds a Reference to each source variable (here, one to the survey variable and one to the admin variable), even though they live in different studies.

    Q5: Why does the linked file get de-identified?

    B. Under governance such as Statistics Canada's Directive on Microdata Linkage, personal information is removed so the linked file is de-identified; researchers often access synthetic versions instead of the original records.

    Exercises¶

    Module 11: Custom Properties, Find, Remove, and Validate¶

    Quiz¶

    Q1: What does set_property do?

    B. set_property(key, value) attaches a custom key-value pair to any DDI item. For example, q.set_property("sensitivity", "high").

    Q2: How do you read all properties on an item?

    C. Use item.properties (no parentheses; it is a property, not a method). It returns a dictionary of all key-value pairs.

    Q3: What does doc.find(identifier) return?

    B. doc.find(identifier) searches all item types and returns the matching item. If nothing matches, it returns None.

    Q4: What does doc.validate() do?

    C. validate() checks whether the document follows the DDI rules. It returns a list of issues. An empty list means the document is valid.

    Q5: What does doc.remove(identifier) do?

    C. doc.remove(identifier) finds the item with that identifier, removes it from the document, and returns True. If no item has that identifier, it returns False.

    Module 12: Custom Fields: Extend the Standard for Your Organization¶

    Quiz¶

    Q1: Why can you add custom fields to a DDI document?

    B. DDI is designed to be extended. UserAttributePair is a standardized extension point, so your custom fields stay inside valid DDI XML.

    Q2: Which DDI element stores a custom key-value field?

    B. set_property writes an r:UserAttributePair with an AttributeKey and an AttributeValue, the standard's extension point for custom fields.

    Q3: What happens to custom fields when you save and reopen a file?

    B. Because they live inside standard DDI, custom fields round-trip. Any DDI-aware tool preserves them, even one that does not know what they mean.

    Q4: When should you use UserID instead of a custom property?

    A. Use UserID (with a type_of_user_id) when the value is an identifier from another system, such as an internal catalogue number. Use a custom property when the value describes the item.

    Q5: Why namespace custom keys like myorg:retention_policy?

    B. A namespace prefix is a convention that keeps your organization's custom fields distinct, which matters if two DDI files are ever merged.

    Quiz¶

    Q1: What is data linkage?

    B. Data (microdata) linkage combines records from different files that describe the same person, household, or business, using the variables they have in common.

    Q2: What is the linkage key?

    B. The linkage key is the common variable (here, anon_id) used to join records that belong to the same unit. We tag it with set_property("linkage_role", "key").

    Q3: How does deterministic linkage differ from probabilistic linkage?

    A. Deterministic linkage matches on a reliable exact key. Probabilistic linkage combines weighted agreement across several fields (name, date of birth, sex, postal code) and applies a threshold.

    Q4: How do you record that a linked variable draws on two source files?

    B. source_variable_references holds a Reference to each source variable (here, one to the survey variable and one to the admin variable), even though they live in different studies.

    Q5: Why does the linked file get de-identified?

    B. Under governance such as Statistics Canada's Directive on Microdata Linkage, personal information is removed so the linked file is de-identified; researchers often access synthetic versions instead of the original records.

    Module 13: Update and Version Your Documents¶

    Quiz¶

    Question 1: What does increment_minor_version() do?

    B. increment_minor_version() increases the second number and resets the third number to zero. So 1.0.0 becomes 1.1.0.

    Question 2: What does a version rationale record?

    C. A version rationale is a short note that explains why a change was made. It helps future users understand the history of the document.

    Question 3: What does version_responsibility track?

    B. version_responsibility is a text field that records who made or approved the change. It could be a person's name or a team name.

    Question 4: When should you use a major version increment?

    C. A major version increment (1.0.0 to 2.0.0) signals a large, potentially breaking change. Small additions use a minor increment. Typo fixes use a sub-version increment.

    Question 5: You reword a question and bump its version. What else must you do?

    C. A DDI reference names one exact version. After the bump, the variable's question_references (and any QuestionConstruct that asks the question) still name the old version, so replace them with question.to_reference(). doc.lint() reports a ddi.reference.integrity error for each one you miss.

    Question 6: How do you switch a variable from one code list to another?

    A. set_coded() replaces the variable's representation with one that references the new code list. Then bump the variable's version, record a rationale, and remove the old code list if nothing else uses it.

    Question 7: You update 30 variables from a new data file. When should you build the new record layout?

    B. A record layout holds references to the variables, and each reference names a version. Built before the bumps, it would point at the old versions. Built after, variable.to_reference() gives the new ones.

    Quiz¶

    Question 1: What does ddi.open_ddi() do?

    B. ddi.open_ddi() reads a DDI XML file and returns a Document object that you can inspect and modify.

    Question 2: What does validate=True do when you call open_ddi()?

    B. When you pass validate=True, open_ddi() runs the DDI schema check during loading. If the file has errors, you get an error message right away.

    C. ddi-l preserves unknown XML elements. This is called the round-trip guarantee. Content that ddi-l does not recognize passes through unchanged.

    B. ddi validate checks the file against the DDI schema. If the file follows all the rules, it prints "Document is valid." If not, it prints a list of errors in JSON format.

    Question 2: What does exit code 0 mean?

    C. Exit code 0 means success. The command finished without errors. Scripts and pipelines use exit codes to decide what to do next.

    Question 3: What does ddi to-json produce?

    B. ddi to-json converts a DDI XML file into JSON format. JSON is a text format that many tools and programming languages can read.

    Track A: University Student: Document Your Thesis Dataset: Sample solution

    One complete script for all the steps above, using thesis-data.csv.

    import csv
import ddi_l as ddi
from ddi_l.models.base import VersionRationale, InternationalString

# Read CSV
with open("thesis-data.csv") as f:
    columns = csv.DictReader(f).fieldnames

# Create v1.0
doc = ddi.new_study(title="Thesis Dataset", agency="university.edu")
# How each column was asked. StudentID is assigned and AnxietyScore is computed
# from a questionnaire, so neither gets a question of its own.
QUESTIONS = {
    "Age": "How old are you?",
    "Gender": "What is your gender?",
    "YearOfStudy": "What year of your program are you in?",
    "Program": "Which program are you enrolled in?",
    "StudyHours": "On a typical day, how many hours do you study?",
    "SleepHours": "On a typical night, how many hours do you sleep?",
    "WorkHours": "How many hours a week do you work for pay?",
    "ExerciseDays": "On how many days last week did you exercise?",
    "StressLevel": "On a scale of 1 to 10, how stressed have you felt this term?",
    "SoughtSupport": "Have you sought support from campus services this term?",
}
for col in columns:
    wording = QUESTIONS.get(col)
    q = doc.add_question(text=wording) if wording else None
    v = doc.add_variable(name=col, question=q)
    v.set_property("source", "Primary survey data")

doc.add_concept(name="Demographics")
doc.add_concept(name="Academic Performance")
doc.add_concept(name="Well-Being")
doc.add_universe(name="Undergraduate students at University X")

doc.save("thesis-v1.xml")
issues = doc.validate()
print(f"v1 valid: {not issues}")

# Update to v1.1
doc = ddi.open_ddi("thesis-v1.xml")
q_new = doc.add_question(text="What is the student's GPA?")
v_new = doc.add_variable(name="GPA", question=q_new)

study = doc.study_unit
study.increment_minor_version()
study.version_rationales.append(
    VersionRationale(
        descriptions=[InternationalString(text="Added GPA variable for analysis")]
    )
)
study.version_responsibility = "Thesis Author"
doc.save("thesis-v1.1.xml")
print(f"v1.1 valid: {not doc.validate()}")
