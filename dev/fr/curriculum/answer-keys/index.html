    Corrigés¶

    Toutes les solutions des exercices et les réponses aux quiz du programme, sur une seule page, pour les instructeurs. Les apprenants qui suivent un module peuvent plutôt ouvrir la réponse sous chaque exercice et chaque question.

    Cette page est construite à partir des modules à chaque génération du site : elle leur correspond donc toujours.

    Module 1 : Qu'est-ce que les métadonnées et pourquoi sont-elles importantes ?¶

    Exercices¶

    Exercice 1

    Trois de ces éléments, ou d'autres semblables :

    1. Ce que signifie chaque colonne (A est-elle un âge ? En années ou en mois ?)
    2. Qui a été interrogé (des étudiants ? des adultes ? tout le monde ?)
    3. Quand les données ont été collectées

    Exercice 2

    Par exemple : « The Data Documentation Initiative (DDI) is an international standard for describing data from the social, behavioral, economic, and health sciences. » (L'initiative de documentation des données est une norme internationale pour décrire les données des sciences sociales, comportementales, économiques et de la santé.)

    Quiz¶

    Question 1 : Qu'est-ce que les métadonnées ?

    B. Les métadonnées sont des informations sur les données. Elles décrivent ce que les données signifient, d'où elles viennent et comment elles ont été collectées.

    Question 2 : Pourquoi la documentation est-elle importante ?

    C. Sans documentation, les données ne sont que des chiffres et des étiquettes sans contexte. Les gens risquent de mal interpréter ou de mal utiliser les données.

    Question 3 : Que signifie FAIR ?

    B. FAIR signifie Findable (Trouvable), Accessible, Interoperable (Interopérable) et Re-usable (Réutilisable). Ces quatre principes guident la façon dont les données devraient être partagées pour que d'autres puissent les découvrir, les comprendre et les réutiliser. Les métadonnées DDI vous aident à respecter les quatre.

    Question 4 : Que fait ddi-l ?

    B. ddi-l est un paquet Python pour travailler avec les documents de métadonnées DDI. Il gère le XML pour que vous puissiez vous concentrer sur vos données.

    Module 2 : Préparer votre environnement Python¶

    Exercices¶

    Exercice 1

    La dernière ligne commence par Successfully installed et mentionne ddi-l-... parmi les paquets (la version peut varier). Si les paquets étaient déjà installés, pip affiche plutôt Requirement already satisfied.

    Exercice 2

    La version installée, par exemple 0.1.0 ou plus récente.

    Exercice 3

    Huit dans ddi-l 0.1.0 : validate, to-json, from-json, roundtrip, lint, versions, to-jsonld et serve. Les versions ultérieures peuvent en ajouter.

    Quiz¶

    Question 1 : Quelle est la version minimale de Python pour ddi-l ?

    C. ddi-l nécessite Python 3.11 ou plus récent.

    Question 2 : Quelle commande affiche l'aide de l'outil en ligne de commande ddi-l ?

    C. La commande ddi --help affiche la liste des commandes disponibles dans l'outil en ligne de commande ddi-l.

    Question 3 : Que fait pip install ?

    B. pip install télécharge un paquet depuis PyPI (le Python Package Index) et l'installe sur votre ordinateur pour que vous puissiez l'utiliser.

    Module 3 : Créer votre première étude DDI¶

    Exercices¶

    Exercice 1

    import ddi_l as ddi

doc = ddi.new_study(title="Student Well-Being Survey", agency="university.edu")

q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="How would you rate your health?")
q3 = doc.add_question(text="How many hours do you sleep per night?")

print(f"Questions: {len(doc.questions)}")
doc.save("well-being.xml")

    Exercice 2

    Le texte de la question se trouve dans un élément <d:Text>, à l'intérieur de <d:LiteralText>, lui-même dans <d:QuestionText> :

    <d:Text xml:lang="en" isPlainText="true">What is your age?</d:Text>

    Exercice 3

    from ddi_l.models.base import InternationalString

q1.question_texts.append(InternationalString(text="Quel est votre âge ?", lang="fr"))
doc.save("well-being.xml")

    Ouvrez le XML. Vous devriez voir à la fois xml:lang="en" et xml:lang="fr" pour la première question.

    Quiz¶

    Question 1 : Que renvoie ddi.new_study() ?

    B. ddi.new_study() renvoie un objet Document. Vous utilisez cet objet pour ajouter des questions, des variables et d'autres éléments à l'étude.

    Question 2 : Que fait doc.add_question() ?

    B. doc.add_question() ajoute un nouvel élément question à l'étude DDI. Elle renvoie l'objet question pour que vous puissiez l'utiliser plus tard.

    Question 3 : Que fait doc.save() ?

    C. doc.save("filename.xml") écrit le document DDI dans un fichier XML dans votre dossier courant.

    Question 4 : Comment ajouter une traduction française à une question ?

    B. Pour ajouter une traduction, ajoutez un InternationalString avec la nouvelle langue à la liste question_texts de la question. Les deux versions linguistiques sont stockées dans le même élément question. L'option A créerait une toute nouvelle question, pas une traduction d'une question existante.

    Question 5 : Comment compter les questions dans une étude ?

    B. doc.questions vous donne la liste des questions, et len() compte combien d'éléments se trouvent dans cette liste.

    Question 6 : doc.validate() renvoie une liste vide, mais doc.lint() signale des avertissements. Le document est-il du DDI valide ?

    B. Une liste vide renvoyée par doc.validate() signifie que le document respecte le schéma DDI. Les avertissements de lint méritent d'être corrigés, mais ils ne rendent pas le document invalide.

    Module 4 : Ajouter des variables et les associer aux questions¶

    Exercices¶

    Exercice 1

    import ddi_l as ddi

doc = ddi.new_study(title="Student Well-Being Survey", agency="university.edu")

q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="How would you rate your health?")
q3 = doc.add_question(text="How many hours do you sleep per night?")

v1 = doc.add_variable(name="Age", question=q1)
v2 = doc.add_variable(name="HealthRating", question=q2)
v3 = doc.add_variable(name="SleepHours", question=q3)

print(f"Variables: {len(doc.variables)}")

    Exercice 2

    for v in doc.variables:
    print(v.identifier)

    Chaque identifiant est un UUID, par exemple a1b2c3d4-....

    Exercice 3

    Chaque variable est un élément <l:Variable>. Son nom se trouve dans <l:VariableName>, par exemple :

    <l:VariableName>
  <r:String xml:lang="en">Age</r:String>
</l:VariableName>

    L'élément <r:QuestionReference> juste en dessous est le lien vers la question.

    Quiz¶

    Question 1 : Que fait l'argument question= dans doc.add_variable() ?

    B. L'argument question= crée un lien dans le document DDI entre la variable et la question qui a collecté les données.

    Question 2 : Comment lister toutes les variables d'une étude ?

    C. doc.variables renvoie la liste de toutes les variables de l'étude. Vous pouvez utiliser len(doc.variables) pour les compter.

    Question 3 : Une variable est comme _____ dans un tableur.

    C. Une variable est comme une colonne. Chaque colonne contient un type d'information (comme l'âge ou le revenu) pour chaque personne du jeu de données.

    Module 5 : Organiser avec les concepts et les univers¶

    Exercices¶

    Exercice 1

    import ddi_l as ddi

doc = ddi.new_study(title="National Health Survey", agency="health.gc.ca")

q1 = doc.add_question(text="How old are you?")
q2 = doc.add_question(text="What is your weight in kg?")
q3 = doc.add_question(text="How many days per week do you exercise?")
q4 = doc.add_question(text="How many servings of fruit do you eat per day?")

demo = doc.add_concept(name="Demographics")
activity = doc.add_concept(name="Physical Activity")
nutrition = doc.add_concept(name="Nutrition")

doc.add_universe(name="Adults aged 18+ in Canada")

doc.add_variable(name="Age", question=q1, concept=demo)
doc.add_variable(name="Weight", question=q2, concept=demo)
doc.add_variable(name="ExerciseFrequency", question=q3, concept=activity)
doc.add_variable(name="FruitServings", question=q4, concept=nutrition)

print(f"Questions: {len(doc.questions)}")
print(f"Variables: {len(doc.variables)}")
print(f"Concepts: {len(doc.concepts)}")
print(f"Universes: {len(doc.universes)}")
print(f"Schema problems: {len(doc.validate())}")

    Quiz¶

    Question 1 : Qu'est-ce qu'un concept ?

    B. Un concept est une idée abstraite, comme « Demographics » ou « Nutrition ». Les variables mesurent des concepts.

    Question 2 : Qu'est-ce qu'un univers ?

    C. L'univers indique qui l'enquête couvre, par exemple, « Adultes de 18 ans et plus au Canada ».

    Question 3 : Comment liez-vous une variable à un concept ?

    B. Passez l'argument concept= quand vous appelez doc.add_variable().

    Module 6 : D'un tableau CSV ou Excel vers DDI¶

    Quiz¶

    Question 1 : Que vous donne csv.DictReader ?

    B. csv.DictReader lit un fichier CSV. Sa propriété fieldnames retourne les noms de colonnes de la première ligne.

    Question 2 : Comment obtenir les noms de colonnes d'un DataFrame pandas ?

    C. Utilisez df.columns pour obtenir les noms de colonnes d'un DataFrame pandas. Entourez-le de list() pour obtenir une liste simple.

    Question 3 : Que produit le script ?

    B. Le script produit un fichier DDI XML. Ce fichier décrit les données (noms de variables, questions, concepts) mais ne contient pas les données elles-mêmes.

    Question 4 : Pourquoi devriez-vous ajouter des concepts après avoir importé les colonnes ?

    C. Les concepts regroupent les variables liées entre elles. Sans eux, vous n'avez qu'une liste plate de noms. Les concepts ajoutent du sens et de la structure.

    Module 6 : Ouvrir, modifier et ré-enregistrer des fichiers DDI existants¶

    Exercices¶

    Exercice 1

    import ddi_l as ddi

# Create and save
doc = ddi.new_study(title="Census 2024", agency="stats.example.org")
q1 = doc.add_question(text="What is your age?")
q2 = doc.add_question(text="What is your gender?")
v1 = doc.add_variable(name="Age", question=q1)
v2 = doc.add_variable(name="Gender", question=q2)
doc.save("census-2024.xml")
print("Saved.")

# Re-open and inspect
doc2 = ddi.open_ddi("census-2024.xml")
print(f"Questions: {len(doc2.questions)}")
print(f"Variables: {len(doc2.variables)}")

    Exercice 2

    q3 = doc2.add_question(text="What is your marital status?")
q4 = doc2.add_question(text="How many people live in your household?")
v3 = doc2.add_variable(name="MaritalStatus", question=q3)
v4 = doc2.add_variable(name="HouseholdSize", question=q4)

errors = doc2.validate()
if errors:
    print("Validation errors:", errors)
else:
    print("Document is valid.")
    doc2.save("census-2024-updated.xml")
    print("Saved updated file.")

    Exercice 3

    doc3 = ddi.open_ddi("census-2024-updated.xml")
print(f"Questions: {len(doc3.questions)}")
print(f"Variables: {len(doc3.variables)}")

    Quiz¶

    Question 1 : Que fait ddi.open_ddi() ?

    B. ddi.open_ddi() lit un fichier DDI XML et retourne un objet Document que vous pouvez inspecter et modifier.

    Question 2 : Que fait validate=True quand vous appelez open_ddi() ?

    B. Quand vous passez validate=True, open_ddi() exécute la vérification du schéma DDI pendant le chargement. Si le fichier contient des erreurs, vous recevez un message d'erreur tout de suite.

    Question 3 : Le contenu existant est-il perdu quand vous ouvrez un fichier, ajoutez des éléments et l'enregistrez ?

    C. ddi-l préserve les éléments XML inconnus. C'est ce qu'on appelle la garantie aller-retour. Le contenu que ddi-l ne reconnaît pas passe sans être modifié.

    Module 7 : Valider depuis la ligne de commande¶

    Exercices¶

    Exercice 1

    ddi validate census-2024-updated.xml

    Exercice 2

    ddi to-json census-2024-updated.xml --indent 2 > census-2024-updated.json
wc -l census-2024-updated.json

    La commande wc -l compte le nombre de lignes dans un fichier. Votre nombre dépendra de la quantité de contenu dans le fichier.

    Exercice 3

    ddi roundtrip census-2024-updated.xml --output census-2024-roundtrip.xml
ls -l census-2024-updated.xml census-2024-roundtrip.xml

    La commande ls -l affiche les tailles des fichiers. Les deux fichiers devraient être proches en taille. De petites différences d'espacement sont normales.

    Quiz¶

    Question 1 : Que fait la commande ddi validate ?

    B. ddi validate vérifie le fichier par rapport au schéma DDI. Si le fichier suit toutes les règles, elle affiche « Document is valid. » Sinon, elle affiche une liste d'erreurs au format JSON.

    Question 2 : Que signifie le code de sortie 0 ?

    C. Le code de sortie 0 signifie succès. La commande s'est terminée sans erreur. Les scripts et les pipelines utilisent les codes de sortie pour décider quoi faire ensuite.

    Question 3 : Que produit ddi to-json ?

    B. ddi to-json convertit un fichier DDI XML au format JSON. Le JSON est un format texte que beaucoup d'outils et de langages de programmation peuvent lire.

    Module 7 : Construire des listes de codes et des vocabulaires contrôlés¶

    Quiz¶

    Question 1 : Qu'est-ce qu'une liste de codes ?

    B. Une liste de codes définit les réponses autorisées pour une question. Par exemple, « Male / Female / Other » pour le genre.

    Question 2 : Comment ajouter une catégorie à un document ?

    B. Utilisez doc.add_item(Category, name="Male"). Vous devez d'abord importer Category depuis ddi_l.models.logicalproduct.

    Question 3 : Comment obtenir toutes les catégories d'un document ?

    C. Utilisez doc.items(Category) pour obtenir la liste de tous les éléments Category. Cela fonctionne pour tout type DDI enregistré.

    Question 4 : Pourquoi les listes de codes sont-elles importantes ?

    C. Les listes de codes empêchent les réponses désordonnées et incohérentes. Elles permettent aussi à différentes enquêtes de partager le même ensemble de valeurs autorisées, rendant les données comparables.

    Module 8 : D'un tableau CSV ou Excel vers DDI¶

    Exercices¶

    Exercice 1

    import csv
import ddi_l as ddi

with open("survey_sample.csv") as f:
    reader = csv.DictReader(f)
    columns = reader.fieldnames

# La question que chaque colonne enregistre, formulée comme les répondants l'ont lue
QUESTIONS = {
    "age": "Quel âge avez-vous ?",
    "gender": "Quel est votre genre ?",
    "income": "Quel a été votre revenu total l'an dernier, avant impôts ?",
    "education_level": "Quel est le plus haut niveau de scolarité que vous avez atteint ?",
}

doc = ddi.new_study(title="Household Survey", agency="research.org")
for col in columns:
    libelle = QUESTIONS.get(col)
    # Une colonne qu'on n'a demandée à personne, comme respondent_id, n'a pas de question
    q = doc.add_question(text=libelle, lang="fr") if libelle else None
    doc.add_variable(name=col, question=q)

doc.save("household-survey.xml")
print(f"Variables: {len(doc.variables)}")  # -> Variables: 5

    Module 8 : Traduire un devis de questionnaire en logique de flux DDI¶

    Quiz¶

    Question 1 : Quelle construction DDI représente une section ordonnée d'un questionnaire ?

    Quiz¶

    Question 1 : Qu'est-ce que le couplage de données ?

    B. Le couplage de (micro)données combine des enregistrements de différents fichiers qui décrivent la même personne, le même ménage ou la même entreprise, au moyen des variables qu'ils ont en commun.

    B. source_variable_references contient une Reference vers chaque variable source (ici, une vers la variable d'enquête et une vers la variable administrative), même si elles vivent dans des études différentes.

    B.     Quiz¶

    Question 1 : Que fait set_property ?

    B. set_property(key, value) attache une paire clé-valeur personnalisée à tout élément DDI. Par exemple, q.set_property("sensitivity", "high").

    Question 2 : Comment lire toutes les propriétés d'un élément ?

    C. Utilisez item.properties (sans parenthèses ; c'est une propriété, pas une méthode). Cela retourne un dictionnaire de toutes les paires clé-valeur.

    Question 3 : Que retourne doc.find(identifier) ?

    B. doc.find(identifier) cherche dans tous les types d'éléments et retourne celui qui correspond. Si rien ne correspond, il retourne None.

    Question 4 : Que fait doc.validate() ?

    C. validate() vérifie si le document respecte les règles DDI. La méthode retourne une liste de problèmes. Une liste vide signifie que le document est valide.

    Question 5 : Que fait doc.remove(identifier) ?

    C. doc.remove(identifier) trouve l'élément avec cet identifiant, le supprime du document et retourne True. Si aucun élément n'a cet identifiant, il retourne False.

    Module 12 : Champs personnalisés : étendre la norme pour votre organisation¶

    Quiz¶

    Question 1 : Pourquoi pouvez-vous ajouter des champs personnalisés à un document DDI ?

    B. DDI est conçu pour être étendu. UserAttributePair est un point d'extension normalisé, de sorte que vos champs personnalisés restent dans du XML DDI valide.

    Question 2 : Quel élément DDI stocke un champ clé-valeur personnalisé ?

    B. set_property écrit un r:UserAttributePair avec un AttributeKey et un AttributeValue, le point d'extension de la norme pour les champs personnalisés.

    Question 3 : Qu'advient-il des champs personnalisés lors de l'enregistrement et de la réouverture d'un fichier ?

    B. Parce qu'ils vivent dans du DDI standard, les champs personnalisés font un aller-retour. Tout outil compatible DDI les préserve, même un qui ne sait pas ce qu'ils signifient.

    Question 4 : Quand utiliser UserID plutôt qu'une propriété personnalisée ?

    A. Utilisez UserID (avec un type_of_user_id) quand la valeur est un identifiant provenant d'un autre système, comme un numéro de catalogue interne. Utilisez une propriété personnalisée quand la valeur décrit l'élément.

    Question 5 : Pourquoi préfixer les clés personnalisées comme myorg:retention_policy ?

    B. Un préfixe d'espace de noms est une convention qui garde les champs personnalisés de votre organisation distincts, ce qui compte si deux fichiers DDI sont un jour fusionnés.

    Module 13 : Mettre à jour et versionner vos documents¶

    Quiz¶

    Question 1 : Que fait increment_minor_version() ?

    B. increment_minor_version() augmente le deuxième nombre et remet le troisième nombre à zéro. Donc 1.0.0 devient 1.1.0.

    Question 2 : Qu'enregistre une justification de version ?

    C. Une justification de version est une courte note qui explique pourquoi un changement a été fait. Elle aide les futurs utilisateurs à comprendre l'historique du document.

    Question 3 : Que suit version_responsibility ?

    B. version_responsibility est un champ texte qui enregistre qui a fait ou approuvé le changement. Ce peut être le nom d'une personne ou le nom d'une équipe.

    Question 4 : Quand devez-vous utiliser une augmentation de version majeure ?

    C. Une augmentation de version majeure (1.0.0 à 2.0.0) signale un grand changement qui peut causer des problèmes. Les petits ajouts utilisent une augmentation mineure. Les corrections de fautes utilisent une augmentation de sous-version.

    Question 5 : Vous reformulez une question et augmentez sa version. Que devez-vous faire d'autre ?

    C. Une référence DDI désigne une version précise. Après l'augmentation, les question_references de la variable (et tout QuestionConstruct qui pose la question) désignent encore l'ancienne version ; remplacez-les par question.to_reference(). doc.lint() signale une erreur ddi.reference.integrity pour chacune que vous oubliez.

    Question 6 : Comment faire passer une variable d'une liste de codes à une autre ?

    A. set_coded() remplace la représentation de la variable par une représentation qui désigne la nouvelle liste de codes. Augmentez ensuite la version de la variable, notez une justification, et retirez l'ancienne liste de codes si plus rien ne l'utilise.

    Question 7 : Vous mettez à jour 30 variables à partir d'un nouveau fichier de données. Quand devez-vous construire le nouveau schéma d'enregistrement ?

    B. Un schéma d'enregistrement contient des références aux variables, et chaque référence désigne une version. Construit avant les augmentations, il pointerait vers les anciennes versions. Construit après, variable.to_reference() donne les nouvelles.

    Quiz¶

    Question 1 : Pourquoi pouvez-vous ajouter des champs personnalisés à un document DDI ?

    B. DDI est conçu pour être étendu. UserAttributePair est un point d'extension normalisé, de sorte que vos champs personnalisés restent dans du XML DDI valide.

    Question 2 : Quel élément DDI stocke un champ clé-valeur personnalisé ?

    B. set_property écrit un r:UserAttributePair avec un AttributeKey et un AttributeValue, le point d'extension de la norme pour les champs personnalisés.

    Question 3 : Qu'advient-il des champs personnalisés lors de l'enregistrement et de la réouverture d'un fichier ?

    B. Parce qu'ils vivent dans du DDI standard, les champs personnalisés font un aller-retour. Tout outil compatible DDI les préserve, même un qui ne sait pas ce qu'ils signifient.

    Question 4 : Quand utiliser UserID plutôt qu'une propriété personnalisée ?

    A. Utilisez UserID (avec un type_of_user_id) quand la valeur est un identifiant provenant d'un autre système, comme un numéro de catalogue interne. Utilisez une propriété personnalisée quand la valeur décrit l'élément.

    Question 5 : Pourquoi préfixer les clés personnalisées comme myorg:retention_policy ?

    B. Un préfixe d'espace de noms est une convention qui garde les champs personnalisés de votre organisation distincts, ce qui compte si deux fichiers DDI sont un jour fusionnés.

    Module 14 : Ouvrir, modifier et ré-enregistrer des fichiers DDI existants¶

    Quiz¶

    Question 1 : Que fait ddi.open_ddi() ?

    B. ddi.open_ddi() lit un fichier DDI XML et retourne un objet Document que vous pouvez inspecter et modifier.

    Question 2 : Que fait validate=True quand vous appelez open_ddi() ?

    B. Quand vous passez validate=True, open_ddi() exécute la vérification du schéma DDI pendant le chargement. Si le fichier contient des erreurs, vous recevez un message d'erreur tout de suite.

    Question 3 : Le contenu existant est-il perdu quand vous ouvrez un fichier, ajoutez des éléments et l'enregistrez ?

    C. ddi-l préserve les éléments XML inconnus. C'est ce qu'on appelle la garantie aller-retour. Le contenu que ddi-l ne reconnaît pas passe sans être modifié.

    Module 15 : Valider depuis la ligne de commande¶

    Quiz¶

    Question 1 : Que fait la commande ddi validate ?

    B. ddi validate vérifie le fichier par rapport au schéma DDI. Si le fichier suit toutes les règles, elle affiche « Document is valid. » Sinon, elle affiche une liste d'erreurs au format JSON.

    Question 2 : Que signifie le code de sortie 0 ?

    C. Le code de sortie 0 signifie succès. La commande s'est terminée sans erreur. Les scripts et les pipelines utilisent les codes de sortie pour décider quoi faire ensuite.

    Question 3 : Que produit ddi to-json ?

    B. ddi to-json convertit un fichier DDI XML au format JSON. Le JSON est un format texte que beaucoup d'outils et de langages de programmation peuvent lire.

    Quiz¶

    Question 1 : Que fait increment_minor_version() ?

    B. increment_minor_version() augmente le deuxième nombre et remet le troisième nombre à zéro. Donc 1.0.0 devient 1.1.0.

    Question 2 : Qu'enregistre une justification de version ?

    C. Une justification de version est une courte note qui explique pourquoi un changement a été fait. Elle aide les futurs utilisateurs à comprendre l'historique du document.

    Question 3 : Que suit version_responsibility ?

    B. version_responsibility est un champ texte qui enregistre qui a fait ou approuvé le changement. Ce peut être le nom d'une personne ou le nom d'une équipe.

    Question 4 : Quand devez-vous utiliser une augmentation de version majeure ?

    C. Une augmentation de version majeure (1.0.0 à 2.0.0) signale un grand changement qui peut causer des problèmes. Les petits ajouts utilisent une augmentation mineure. Les corrections de fautes utilisent une augmentation de sous-version.

    Question 5 : Vous reformulez une question et augmentez sa version. Que devez-vous faire d'autre ?

    C. Une référence DDI désigne une version précise. Après l'augmentation, les question_references de la variable (et tout QuestionConstruct qui pose la question) désignent encore l'ancienne version ; remplacez-les par question.to_reference(). doc.lint() signale une erreur ddi.reference.integrity pour chacune que vous oubliez.

    Question 6 : Comment faire passer une variable d'une liste de codes à une autre ?

    A. set_coded() remplace la représentation de la variable par une représentation qui désigne la nouvelle liste de codes. Augmentez ensuite la version de la variable, notez une justification, et retirez l'ancienne liste de codes si plus rien ne l'utilise.
